# 谜题与线索设计

第一版采用轻解谜，不追求难度，追求“参与感”。

## 页面机制

- `01-briefing.html`：点击三张简报卡，完成扫描。
- `02-evidence.html`：点击六张证据卡，完成证据墙闭环。
- `03-intercept.html`：输入短码 `TRACE`，破译隐藏消息。
- `04-reconstruction.html`：按正确顺序点击四个事件。
- `05-verdict.html`：点击打印按钮，逐行输出结案报告。

## 案件进度

- 每个正式页面通过 `CONFIG.stage` 标记自身阶段。
- `assets/dossier-nav.js` 会自动注入顶部案件进度轨道。
- 进度使用 `localStorage` 记录已抵达的最远阶段；如果浏览器禁用存储，页面仍可正常浏览。

## 难度约束

- 每页应有明确提示。
- 错误操作要给反馈，不要让用户猜系统是否响应。
- 不设置倒计时。
- 不设置不可逆失败。
- 不依赖外部资源、网络或真实密码。

## 可替换谜题

- 短码可以换成目标昵称、纪念词或内部暗号。
- 证据卡可以换成真实生活细节。
- 事件重构可以换成“认识、熟悉、靠近、确认”的非日期版本。

## 可达性注意

- 所有关键操作使用按钮或链接。
- 页面不依赖颜色作为唯一状态提示。
- `prefers-reduced-motion` 下关闭强动画。
