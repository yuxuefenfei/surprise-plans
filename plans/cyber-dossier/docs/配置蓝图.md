# 配置蓝图

当前正式页面已经使用 `assets/dossier-config.js` 作为统一内容配置。每个页面仍保留一个很薄的 `CONFIG`，只负责合并共享配置与当前页面阶段。

## 顶层信息

```js
const DOSSIER_CONFIG = {
    caseId: "CD-0427",
    targetAlias: "[目标代号]",
    investigatorAlias: "[调查员代号]",  // 预留字段，暂未在页面中使用
    passcode: "TRACE"
};
```

## 页面配置

### `pages.access` — 案件接入页

```js
access: {
    headline: "CASE ACCESS",                        // 主标题
    intro: "你被临时调入一桩异常档案...",              // 引导语
    subIntro: "本调查不涉及危险品...",                 // 副标题（硬编码已抽取）
    bootLines: [                                    // 终端启动日志（数组）
        { text: "> initializing...", className: "terminal-line warn" },
        { text: "> loading target alias: [target]", className: "terminal-line" },
        // ... 每行支持 text 和 className 字段
    ]
}
```

```js
    completeNotice: "全部档案解密扫描完成...",         // 完成提示

```

### `pages.evidence` — 证据墙页

```js
evidence: {
    instruction: "线索与推论已打乱，请配对关联...",   // 页面说明文字（已更新为配对版）
    initialNotice: "3 对关联待配对。",                // 初始提示
    progressNotice: "已配对 {done}/3 对。",           // 进度（{done} 为占位符）
    matchSuccessNotice: "配对成功：{matchText}",      // 配对成功提示（{matchText} 为占位符）
    matchFailNotice: "关联性不足，重新分析。",         // 配对失败提示
    completeNotice: "全部配对完成。证据墙闭环...",    // 完成提示

        ["A01", "反复出现的聊天窗口", "频率异常，但调查员没有关闭。"],
        // ... [编号, 标题, 详情]
```


## 抽取说明

当前已经落地：

- `assets/dossier-config.js`：存放顶层信息和所有页面文案
- `assets/dossier.css`：全局样式、动画和交互效果
- `assets/dossier-nav.js`：注入案件进度轨道 + 页面转场动画

仍保持纯静态，不引入构建工具。每页只负责：

1. 声明当前页面 key 和 stage
2. 引入共享 CSS、配置和进度轨道
3. 保留页面结构与交互逻辑

## 何时需要修改配置

- 要替换人物信息 → 修改 `targetAlias`、`investigatorAlias`
- 要改线索/证据内容 → 修改 `evidence.clues` 和 `evidence.pairs`
- 要改信号节点 → 修改 `intercept.segments`（支持 sequence/tap/wave 三种类型）
- 要改事件重构 → 修改 `reconstruction.scenes` 和 `reconstruction.correctOrder`
- 要改彩蛋内容 → 修改 `verdict.easterEggs`（触发词 + 揭示内容）
- 要改按钮或提示文案 → 修改对应 `pages.*` 下的 `*Notice` / `*Label` 字段
- 要改终端内容 → 修改 `bootLines` / `packetLines` / `initialLines`
- 要改解密相关文案 → 修改 `briefing.encryptedLabel`、`briefing.decryptBtnLabel` 等
